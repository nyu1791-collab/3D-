# 動きの付け方（低コスト）

背景・図・文字を分けて用意し、音声の長さに合わせて動かす考え方のメモ。毎秒の映像を生成しない。元は 2026-10 の別環境の試作記録で、2026-11-01 に本リポジトリのコードと照合した。

**本アプリの映像は、静止画をズーム・パンで動かす疑似3D。** 立体モデルや物理シミュレーションではなく、そう称しない。以下の型も平面の合成であり、立体化の手法ではない。

## 現行の実装

- カメラは `zoom_in`・`zoom_out`（1.00⇔1.12）と `pan_down` の 3 種類。
- ラベルは画像に焼き込まず、独立したテキストトラックに置く。
- 時間はナレーション音声の実測長。字幕はシーン・発話単位で、単語時刻はない。

## 1. 層を分ける

重い部分は一度だけ作り、再利用する。

| 層 | 内容 | 動き |
|---|---|---|
| 背景 | 断面図・俯瞰図のシーン画像 | ゆっくりしたズームかパン |
| 説明 | ラベル、矢印、注目枠 | 言葉に合わせて順に出す |
| 字幕 | 話している文 | 音声に合わせて切り替える |

- 全部を同時に動かすと、見る場所が分からなくなる。一画面で動かすのは原則一か所にする。
- 一画面に要点は一つ。二つになったら場面を分ける。
- 同じ色と同じ動きの型を使い続ける。

## 2. 時刻は音声から取る

- 登場時刻は実音声の長さから決める。30 秒に合わせるために架空の時刻を作らない。
- 言葉と図を対応させるのが理想（「雨水が」→雨水のラベル、「しみ込む」→矢印が伸びる）。ただし単語時刻を取得していないので、シーン内の細かい同期は推定になる。推定を正確な同期と呼ばず、ASR を標準工程へ足さない。迷ったらシーン単位で合わせる。

## 3. 動きの型

5 つあれば足りる。秒数と量は試作で選んだ値で、見て調整する。

1. フェードイン・アウト
2. 下から少し上がって登場（ease-out、約 0.45 秒）
3. 小さく拡大して登場（0.97→1.00）
4. 線が伸びる（ease-in-out、約 0.6 秒）
5. ゆっくりした浮き（±3 px、周期 3 秒）

味付けは必要な時だけ。

- ease-out：最初が速く、最後にゆっくり止まる。画面に入る動きに使う。
- 予備動作：登場の前にわずかに沈む（約 0.12 秒、6 px）。
- 遅れ：線の先端が伸び切った後、わずかに戻って止まる（3 px）。

これらは現行のカメラ 3 種類に含まれない。使うなら CapCut 上の調整か、任意の演出として足す。使えない時は省いて続行し、演出の不足で停止や再生成をしない（AGENTS.md）。

## 4. 書き出しを軽くする

- 部品は透過画像として一度作り、位置・拡大率・透明度だけを計算する。
- 下書きは軽い設定で作る。1080p は 720p の 2.25 倍の画素数。幅と高さは偶数にする。
- フレームを画像ファイルにせず ffmpeg の標準入力へ流す方法（`-f rawvideo -pix_fmt rgb24`）もある。現行は未使用。
- ffmpeg の zoompan はカクつきや停止の報告がある（2015 年の ffmpeg-user の報告で、現行版では未確認）。元の試作は Pillow で位置をずらして回避した。`[現行と異なる]` `render.py` の MP4 書き出しは 2 倍の画像に zoompan をかけている。問題が見えた時の代替として覚えておく。

## 5. 根拠が弱いもの

- 「120〜140 語/分」「20〜30 秒ごとに場面転換」は販売者の経験則で、研究の根拠はない。使うなら目安とする。
- 「字幕が数秒ずれると学習が落ちる」といった数値は出典を確かめられなかった。
- 30fps 固有の指針と zoompan の性能の数値は見つからなかった。
